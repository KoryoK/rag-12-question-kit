# Dify RAG 12問チェックキット v1.0

Difyで作った小さな社内RAGに、**資料内・資料外・条件不足**の質問を4問ずつ、合計12問投げて、回答の内容と引用した規程番号を別々に記録するための手動テスト一式です。架空の規程、12問と事前に決めた合否基準、実験で使ったプロンプトと設定、空欄の記録表、初回12問の実回答を同梱しています。

- ダウンロード（ZIP）: https://github.com/KoryoK/rag-12-question-kit/releases/latest/download/rag-12-question-kit-v1.0.zip
- ZIPの SHA-256: `1c248be597c34479ce58873f55d1382ff2a337fd938be697baeeba0a0447f5b7`
- このリポジトリの各ファイルは、ZIPを展開したものと同じ内容です。
- 解説記事（note）: https://note.com/brainy_phlox8948/n/n30de18315ccd

資料にある質問だけで動作確認を終えているDify開発担当向けの、小さな手動テスト一式です。資料内・資料外・条件不足を別々に確かめます。実在する社内規程は含みません。

## 最初に使うファイル

- `knowledge.txt`：Difyに登録する架空規程。登録するのはこれだけ。
- `questions.csv`：12問と、実行前に決めた合否基準。Difyには登録しない。
- `results-template.csv`：自分の回答・判定を記録する空欄の表。
- `prompt.txt`：実験で使用したInstructions。
- `settings.json`：確認した設定。nullは未確認。自分の実行時はコピーして更新する。
- `example-results.csv`：初回実機検証の実回答。自分の結果で上書きしない。
- `EXAMPLE_REVIEW.md`：内容の採点と引用誤りの記録。

PythonやAPIキーの設定はこのキット自体には不要です。Difyのアカウント、アプリを作る権限、利用可能なチャット・埋め込みモデルが必要です。モデル使用料・credits消費は利用環境に従います。無料で実行できる保証や所要時間の実測はありません。

## Difyでの手順（2026-10-04のCloud画面で確認）

1. 検証専用Chatbotを作成する。既存業務アプリを使わない。
2. Knowledge → Create → Import from fileで`knowledge.txt`を選ぶ。
3. General、Delimiterを`\n\n`、Maximum chunk lengthを1024、overlapを50にする。連続空白・改行・タブの置換ON、URL削除OFF。
4. Preview Chunkで5チャンクを確認する。R01〜R04の見出しと本文が同じチャンクにあることを確認する。ファイルの空行を削除すると変わるので注意。
5. High Quality、embedding=`text-embedding-3-large`、Vector Search、Top K=3、Score Threshold OFF、Rerank OFFでSave & Process。Availableになるまで待つ。
6. ChatbotのKnowledge → Addから登録した知識を選択。Instructionsに`prompt.txt`を貼る。チャットモデルを`gpt-4o-mini`にする。
7. アプリのRetrieval SettingはWeighted Score、Semantic=1、Keyword=0、Top K=4、Score Threshold OFF。モデルのパラメータ上書きスイッチはOFFの状態を使用した。画面の数値表示を実効リクエスト値と同一視しない。
8. Debug & Previewでquestions.csvのA01から順に入力。**毎問Restartして新規会話にする。** 1問につき回答を保存してから次に進む。公開操作は不要。
9. results-template.csvを別名で保存し、run_id、UTC時刻、実回答、根拠画面のファイル名、判定理由を埋める。引用番号の正誤は別欄に残す。応答が返らない場合はinconclusiveで記録し、他の条件の結果に混ぜない。
10. 資料内・資料外・条件不足の各4問を別々に集計する。空欄とinconclusiveは合格に数えない。文章の意味を読んで判定し、単語が含まれているだけで合格にしない。

モデルが利用できなければ、自分の利用可能なモデルで別runを作る。その場合は同条件の再現と呼ばない。同じモデル名でも応答やサービス側の設定が変わり、同文が返る保証はありません。

## 検索取得文と回答の分離

回答本文が挙げた「R03」等は、検索ログの代わりになりません。今回のDebug & PreviewではCitations and AttributionsがONでも、各回答の検索全文を確認できませんでした。元リクエストの取得文を確認できなければretrieved_textを空欄にし、retrieval_statusをunknownにします。

切り分け用の別操作はKnowledge → Retrieval Testing → 同じ質問 → Testです。表示されたチャンクとスコアを保存し、**separate_retrieval_test**として区別します。後から行った検索の結果を、以前の回答に渡された資料として扱わないでください。

初回A04の別検索ではR04(0.65)、R03(0.55)、R02(0.40)が表示されました。元の生成時の取得全文は未確認なので、原因が検索か生成かは断定していません。

## 採点の境界

- A04は窓口名の基準には合格。ただしR03という引用番号は誤り（正しくはR04）。内容と引用を別採点する。
- C01は「国内なら12,000円」だけでは、このキットの厳しめの基準には不合格。国内/海外の確認、または国内の上限と海外対象外の両方が必要。金額捏造とは違う説明不足として記録する。
- 全件「わかりません」なら、資料内A群は不合格。
- 採点基準を変更した場合は別バージョンにする。過去の基準を後から書き換えて見かけの成功数を上げない。

## 自分の題材に差し替える

最初はこの架空規程で操作を確かめ、その後に利用可能な自分の資料へ差し替えます。「正社員/契約社員」のように近い条件を作るときは、正解を資料から確定できるものに限ります。資料外の質問は本当に記載がないか確認します。条件不足の質問には、受け入れる確認質問・条件付き回答を実行前に書きます。

この12問は網羅的な評価ではありません。実務の長文、矛盾する資料、権限別アクセス、個人情報の扱いは検証対象外です。一般的な精度・業務効果・時短の証明として使わないでください。

## 記録の見方

初回例はCodexがブラウザー操作して実行した結果です。利用者本人の顧客実績や研修実績ではありません。UTCの2026-10-03 15時台は日本時間10月4日です。CSVはUTF-8 BOM付き。

キット内の架空規程・質問・記録様式は、自分の検証用にコピー・改変して利用できます。第三者のデータ・記事の転載物は含めていません。検証結果を変更して再配布する場合は、実行条件と変更箇所が分かるようにしてください。
